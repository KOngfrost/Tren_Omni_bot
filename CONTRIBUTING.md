# 🤝 Руководство по участию в разработке (Contributing Guide)

Мы приветствуем вклад любого участника студенческого сообщества и открытого ПО в развитие платформы **OSS Bot**!  
Этот документ описывает процесс разработки, стандарты качества, структуру команды и меры по снижению фактора единственного разработчика (*Bus Factor*).

---

## 👥 Структура сообщества и защита от Bus Factor

Проект поддерживается объединённой командой Студенческого совета университета и независимых контрибьюторов. Для предотвращения рисков зависимости от одного разработчика (*Bus factor mitigation*):

1. **Коллегиальная ответственность**:
   - **Архитектура и Backend (Python/Go)**: ответственные за ядро, Transactional Outbox, схемы БД и API.
   - **Интерфейсы и боты (VK / aiogram)**: ответственные за UX диалогов и LongPoll/Callback обработчики.
   - **Веб-панель (FastAPI, Jinja2, Tailwind)**: ответственные за UI операторов, доступность и защиту от XSS/CSRF.
   - **DevOps и безопасность**: ответственные за Caddy WAF, Docker Compose, PgBouncer, бэкапы и мониторинг.
2. **Полная прозрачность и документирование**:
   - Вся кодовая база задокументирована в каталоге `docs/` и `TECHNICAL_SPEC.md`. Любой новый контрибьютор может развернуть стек за 5 минут по [Руководству по установке](docs/DEPLOYMENT.md).
   - Схема БД визуализирована в [DATABASE_SCHEMA.md](docs/DATABASE_SCHEMA.md).
   - Миграции линейны и версионируются через Alembic.
3. **Открытые Issues и Discussions**:
   - Если Issues были недоступны в форке или репозитории, они открыты для любого пользователя GitHub. Для багов и предложений используйте стандартные шаблоны Issues.

## 🚀 Как внести вклад (Workflow)

### 1. Подготовка окружения
1. Создайте форк репозитория и клонируйте его:
   ```bash
   git clone https://github.com/KOngfrost/Student_bot.git
   cd Student_bot
   ```
2. Создайте виртуальное окружение Python (рекомендуется Python 3.11–3.14):
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # На Windows: .venv\Scripts\activate
   pip install -r requirements.txt -r requirements-dev.txt
   ```
3. Скопируйте шаблон переменных окружения:
   ```bash
   cp .env.example .env
   ```

### 2. Ветвление (Branching Strategy)
- Создавайте ветки от актуальной ветки `master`:
  - `feat/название-фичи` — новая функциональность
  - `fix/описание-бага` — исправление дефекта
  - `docs/описание-документации` — правки документации
  - `perf/оптимизация` — улучшение производительности

### 3. Стандарты качества и линтинг
Перед отправкой изменений обязательно запустите проверки:

```bash
# 1. Форматирование и проверка кода (Ruff)
ruff check .
ruff format --check .

# 2. Статическая типизация (Mypy)
mypy core web scripts bots

# 3. Полный набор автотестов (Pytest)
pytest -v

# 4. Проверка головы миграций Alembic (должна быть строго одна голова)
python -m alembic heads
```

### 4. Создание Pull Request
1. Оформите коммиты по конвенции [Conventional Commits](https://www.conventionalcommits.org/):
   - `feat(scope): краткое описание`
   - `fix(scope): краткое описание`
   - `docs(scope): краткое описание`
2. Откройте Pull Request в ветку `master`.
3. Заполните чек-лист в описании PR.
4. Дождитесь успешного прохождения GitHub Actions CI (линтеры, тесты, проверка секретов).
5. Получите одобрение хотя бы одного мейнтейнера.

## 🔒 Безопасность и раскрытие уязвимостей

Если вы обнаружили потенциальную уязвимость в системе безопасности (2FA, токены, утечка ПДн, инъекции), **не создавайте публичный Issue**.  
Пожалуйста, следуйте правилам из [SECURITY.md](SECURITY.md) для конфиденциального ответственного раскрытия.

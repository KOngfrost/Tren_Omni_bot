## [0.8.5.1] — 2026-09-25

### 🚩 Этап 1. Критические фиксы безопасности и стабильности (Hotfixes)

- **SEC-01 — Закрытие replay-атак в авторизации Telegram WebApp (`backend_go/internal/handlers/handlers.go`)**:
  - После проверки HMAC-подписи добавлена строгая проверка свежести `auth_date`: запросы старше
    24 часов (`86400` секунд) и даты из будущего (допуск 30 секунд на расхождение часов) отклоняются
    со статусом `401`.
  - Отсутствующий/некорректный `auth_date` и невалидный JSON пользователя больше не приводят
    к ложной авторизации.
  - Добавлены регрессионные тесты `backend_go/internal/handlers/handlers_test.go`
    (свежесть/истечение `auth_date`, подпись чужим токеном, чужой Telegram ID,
    ответ `503` при неинициализированном пуле БД).
- **B1 — Устранение Null Pointer Panic при старте Go-бэкенда (`cmd/server/main.go`, `internal/database/db.go`, `internal/redis/redis.go`)**:
  - Ошибка подключения к PostgreSQL или Redis теперь завершает процесс (`log.Fatalf`): контейнер
    перезапускается оркестратором вместо работы в «полуживом» состоянии с `database.Pool == nil`.
  - `ConnectDB` выполняет до 3 попыток ping с паузой 1 секунда и возвращает ошибку, если БД недоступна.
- **B2 — Обработка SQL-ошибок в Go API (`internal/handlers/handlers.go`)**:
  - Убрано игнорирование ошибок `_ = database.Pool.QueryRow(...)`: при сбое БД клиент получает
    `500 Internal Server Error` с JSON-описанием вместо ложных нулевых данных со статусом `200`.
  - Добавлены проверки `rows.Err()`, защита от `nil`-пула (`503`) и различение нарушения
    UNIQUE-ограничения (`400`) от прочих ошибок БД (`500`).
- **SEC-06 — Исключение утечки пароля БД при Docker Exec (`bots/telegram/handlers/backup.py`)**:
  - `PGPASSWORD` больше не передаётся через `Env` exec-процесса (значение было видно в
    `/exec/{id}/json`): пароль загружается в контейнер файлом `.pgpass` с правами `0600`
    через Docker Archive API, передаётся `pg_dump` через `PGPASSFILE` и гарантированно
    удаляется из контейнера после завершения команды.
  - В `bots/telegram/docker_client.py` добавлен метод `upload_file()` (`PUT /containers/{id}/archive`).
- **SEC-07 / 152-ФЗ — Прекращение отправки дампов с ПДн через Telegram (`bots/telegram/handlers/backup.py`)**:
  - Сырой `.sql.gz` больше не пересылается документом в чат: дамп сохраняется только в защищённом
    локальном каталоге (каталог `0700`, файл `0600`, ротация 7 дней), а администратор получает
    отчёт: статус, размер, время создания и SHA-256 файла.
  - SHA-256 добавлен и в уведомление планового бэкапа (`bots/telegram/monitor_service.py`).
  - Обновлены тесты (`tests/test_tg_monitor.py`) и документация (`TECHNICAL_SPEC.md`,
    справка `/backup` в `bots/telegram/handlers/base.py`).

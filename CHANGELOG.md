# История изменений (Changelog)

Все ключевые изменения проекта документируются в этом файле.  
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), проект придерживается [семантического версионирования (SemVer)](https://semver.org/).

---

## [0.8.3.5] — 2026-09-18

### Исправлено и улучшено
- **Docker Compose & DevOps**:
  - Настроены жесткие ограничения оперативной памяти (`mem_limit` и `memswap_limit`) для всех 8 сервисов для предотвращения OOM Killer.
  - Добавлены healthcheck-проверки для сервисов `prometheus` и `tg-monitor`.
- **Конфигурация & Безопасность**:
  - `core/config.py`: убран `extra="allow"` в пользу `extra="ignore"`, чтобы опечатки в `.env` не попадали в модель настроек.
  - Устранен баг переопределения `REPORT_EMAILS` на уровне класса через прямой `os.getenv()`, обходивший валидаторы Pydantic.
- **Оптимизация кода**:
  - `core/ticket_service.py`: удален дублирующий словарь `STATUS_LABELS` (используется прямой `TicketStatus.value`), удален устаревший метод `create_anonymous_ticket`.
  - `bots/vk/handlers/admin.py`: парсинг статусов переведен на прямой перебор enum `TicketStatus`.
  - `core/models.py`: поле `FAQNode.depth` аннотировано как `ClassVar[int]`, исключая конфликт с маппингом SQLAlchemy.
- **Интерфейс & Ассеты**:
  - Синхронизированы версии ассетов и бейджи веб-панели до `v0.8.3.5`.

## [0.8.3] — 2026-09-16

### Добавлено
- **Telegram-бот мониторинга и Devops-управления для главного администратора**:
  - Строгий контроль доступа: бот отвечает исключительно пользователю с `TELEGRAM_ADMIN_ID` из `.env`.
  - Мониторинг ресурсов сервера: загрузка CPU, памяти RAM, свободного места на диске и времени аптайма с наглядными шкалами.
  - Состояние Docker-контейнеров: статус, здоровье (healthy/unhealthy), вывод карточки по команде `/status`.
  - Автоматические алерты при сбоях: мгновенное уведомление в Telegram при переходе контейнера в `unhealthy` или неожиданном падении, уведомление при восстановлении сервиса, защита от повторного спама.
  - Интерактивное управление через инлайн-кнопки:
    - Перезапуск отдельных контейнеров или всего стека в один клик (`/restart`).
    - Просмотр последних 35 строк логов любого контейнера (`/logs`).
    - Безопасная перезагрузка физического сервера с подтверждением (`/reboot`).
  - Сервис `tg-monitor` в `docker-compose.yml` с прямым доступом к Docker Engine API через `/var/run/docker.sock`.

- **Модуль мероприятий и регистрации**:

- **Интерфейс веб-панели**:
  - Обновлён дизайн карточек и элементов управления (стиль Glassmorphism с матовым размытием `backdrop-filter: blur(14px)`).
  - Сбалансированная цветовая схема в светлой теме с мягкими акцентами.
  - Удалены лишние эмодзи из служебных заголовков, скриптов и веб-интерфейса для строгого делового стиля.
  - Обновлён сайдбар: сквиркл-аватары с первой буквой имени, векторные SVG-иконки, отображение роли оператора.

### Исправлено
- **Двухфакторная аутентификация (2FA)**:
  - Устранён дедлок автоотправки формы входа при вводе 6 цифр (зависание в статусе «Проверка...»).
  - Корректная обработка `401 Unauthorized` в фоновых скриптах без цикличных запросов.
  - Исправлен `AttributeError` при обращении к признаку активности событий в боте.

## [0.8.1] — 2026-09-15

### Безопасность
- **Startup Guard и Bootstrap Guard**:
  - Автоматическая проверка конфигурации при старте (`core/startup_guard.py`).
  - Блокировка запуска в режиме `production` при обнаружении паролей по умолчанию (`admin123`, `changeme` и т.д.).
- **Харденинг 2FA и защита от перебора**:
  - Лимит попыток ввода OTP-кода (не более 5 ошибок) и повторной отправки (не более 3 раз).
  - Хеширование одноразовых кодов с помощью Argon2id и хранение в Redis с TTL.
  - Возврат корректных HTTP-статусов `401` и `429 Too Many Requests` с заголовком `Retry-After`.

### Оптимизация и надежность
- **Ускорение поиска**: добавлены триграммные GIN-индексы PostgreSQL (`pg_trgm`) для быстрого нечёткого поиска по тикетам и базе знаний.
- **Целостность данных**: настроены внешние ключи с правилами каскадного удаления и обнуления (`ON DELETE CASCADE` / `SET NULL`).
- **Disaster Recovery**: добавлены скрипты резервного копирования и восстановления с проверкой контрольных сумм SHA-256 (`scripts/backup.ps1`, `scripts/restore.ps1`).
- **Мультиязычность (i18n)**: заложена основа локализации интерфейса и сообщений (RU/EN).

## [0.8.0] — 2026-09-08

### Добавлено
- **Стандартизированные Excel-отчёты**:
  - Генерация отчёта строго на 5 листов: сводная аналитика + отдельные листы по 4 отделам («Жилищно-бытовой», «Информационный», «Корпоративный», «Культурно-массовый»).
- **Модульная структура VK-бота**:
  - Разделение обработчиков на доменные пакеты `bots/vk/handlers/` на базе `BotLabeler`.
- **REST API v1**:
  - Публичные эндпоинты `/api/v1` со строгой типизацией Pydantic v2 и документацией Swagger (`/docs`).
- **Redis-инфраструктура**:
  - Распределённые сессии пользователей веб-панели (`RedisSessionMiddleware`).
  - Кэширование справочников с инвалидацией по тегам.
  - Блокировки воркеров Outbox через Redis (совместимо с PgBouncer в режиме транзакций).

### Безопасность
- Единый экран ввода 2FA с автовставкой кода и обратным отсчётом таймера.
- Ограничение доступа к журналу аудита и выгрузке логов только для `SUPERADMIN`.
- Контроль синхронизации времени между приложением и PostgreSQL на эндпоинте `/health`.

## [0.7.0] — 2026-08-25

### Добавлено
- Внедрение пулера соединений **PgBouncer** для снижения нагрузки на PostgreSQL при всплесках трафика.

## [0.1.0 – 0.6.0] — MVP и базовая функциональность

- Реализация ядра системы на Python 3.11+ и SQLAlchemy 2.0 (asyncpg).
- Гарантированная доставка сообщений студентам через паттерн **Transactional Outbox**.
- VK-бот для приёма обращений студентов по отделам.
- Веб-панель управления на FastAPI и Jinja2 шаблонах.
- Базовые миграции структуры базы данных Alembic.
- Интеграция со скриптами создания администраторов и базовым резервным копированием.

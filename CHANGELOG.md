# История изменений (Changelog)

Все ключевые изменения проекта документируются в этом файле.  
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), проект придерживается [семантического версионирования (SemVer)](https://semver.org/).

---

## [0.8.3.11] — 2026-09-24

### Исправлено
- **VK Бот — сопоставление глобальных и локальных номеров заявок**:
  - `bots/vk/handlers/student.py`: поддержан поиск заявки студента сначала по глобальному номеру `Ticket.id` (который бот присылает при создании и в ответах оператора), с fallback на локальный порядковый номер в списке последних заявок. Устранена ошибка «Заявка не найдена» и отправка ответа не в тот тикет.
  - `core/ticket_service.py`: добавлена функция `get_user_ticket_by_id(vk_id, ticket_id)` с проверкой прав владения тикетом.
- **PgBouncer интеграция**:
  - `docker-compose.yml`: сервисы `bot` и `web-admin` переведены на подключение через `pgbouncer:6432` (`migrate` сохранён на прямой порт `db:5432`).
  - `core/config.py`: свойства `db_host` и `db_port` автоматически возвращают `pgbouncer:6432` при включенном `DB_USE_PGBOUNCER=true`.
- **Rate limiting за прокси и mesh-сетью Tailscale**:
  - `web/routes/auth.py`: добавлена функция `is_trusted_proxy` с поддержкой проверки CIDR-подсетей и loopback-адресов. Заголовок `X-Forwarded-For` корректно обрабатывается от доверенных прокси, устраняя риск общей блокировки всех администраторов.
- **Telegram Monitor — безопасность и управление**:
  - `bots/telegram/bot.py`: команда `/reboot` переведена на корректный и безопасный перезапуск всех контейнеров проекта с уведомлением о необходимости SSH для перезагрузки хоста.
  - `Dockerfile.monitor`: добавлен непривилегированный пользователь `appuser` (UID 1000) и группа `docker` (GID 988), устраняющие запуск контейнера из-под `root`.
- **Планировщик ежедневных отчётов**:
  - `core/reporting.py`: добавлен механизм повторных попыток отправки отчёта (с интервалом 5 минут) при кратковременных сбоях VK API/SMTP в 09:00, а также автоматическая отправка неотправленного суточного отчёта при рестарте сервиса после часа X.

## [0.8.3.10] — 2026-09-24

### Исправлено
- **VK LongPoll отказоустойчивость и автовосстановление**:
  - Реализован кастомный `RobustBotPolling`, устраняющий зависание бота при ошибках сессии VK API (`VKAPIError_3: Not found` и др.).
  - Автоматический сброс кэшированного сервера (`server = None`) при 3+ повторных ошибках LongPoll вместо бесконечного цикла `Unable to make request to BotPolling, retrying...` с протухшим ключом.
  - Добавлены ретраи с экспоненциальным backoff в `get_server()` для методов `groups.getById` и `groups.getLongPollServer`.
  - Привязка `touch_heartbeat()` непосредственно к циклу опроса LongPoll, что позволяет docker healthcheck мгновенно выявлять зависание сети.

## [0.8.3.9] — 2026-09-19

### Исправлено и улучшено
- **Комплексный аудит и исправление системных багов**:
  - `core/reporting.py`: исправлено переполнение `random_id` (диапазон `2**31 - 1`), актуализирован docstring `REPORT_CHUNK_SIZE`.
  - `core/database.py`: добавлен lazy guard для `async_session_maker` при `engine is None`.
  - `core/cache.py`: устранено задвоение счётчика удалённых ключей в `cache_delete_pattern`.
  - `core/outbox.py`, `core/config.py`: параметры очереди outbox перенесены в Pydantic `Settings`.
  - `core/bulk_import.py`: добавлена санитизация Excel-ячеек `_sanitize_excel_cell()` от Formula/CSV Injection.
  - `core/ticket_service.py`: очищен избыточный `tuple()` в фильтрах SQLAlchemy.
  - `bots/vk/handlers/faq.py`: исправлен regex FAQ-хендлера, исключён ложный перехват произвольных чисел.
  - `bots/vk/handlers/reports.py`: добавлены fallback-хендлеры FSM со сбросом состояния при ошибках ввода даты; добавлено уведомление об отсутствии прав админа.
  - `bots/vk/handlers/student.py`, `bots/vk/keyboards.py`: добавлена клавиатура с кнопкой «Создать заявку» при подсказке из базы знаний.
  - `bots/telegram/`: таймаут клиента увеличен до 120с (`docker_client.py`), добавлена проверка наличия бинарников перезагрузки (`shutil.which`) в `/reboot`, учтён лимит 50 МБ Telegram Bot API для бэкапов.
  - `web/routes/settings.py`: синхронизировано имя cookie оформления (`app_glass_effect`).
  - `docker-compose.yml`: сокет Docker переведён в read-only (`:ro`), исправлен healthcheck сервиса `tg-monitor` на проверку через Python, добавлены флаги `--no-auth-warning`.

## [0.8.3.5] — 2026-09-18

### Исправлено и улучшено
- **Docker Compose & DevOps**:
  - Настроены жесткие ограничения оперативной памяти (`mem_limit` и `memswap_limit`) для всех 8 сервисов для предотвращения OOM Killer.
  - Добавлены healthcheck-проверки для сервисов `prometheus` и `tg-monitor`.
- **Конфигурация & Безопасность**:
  - `core/config.py`: убран `extra="allow"` в пользу `extra="ignore"`, чтобы опечатки в `.env` не попадали в модель настроек.
  - Устранен баг переопределения `REPORT_EMAILS` на уровне класса через прямой `os.getenv()`, обходивший валидаторы Pydantic.
- **Оптимизация кода**:
  - `core/ticket_service.py`: удален дублирующий словарь `STATUS_LABELS` (используется прямой `TicketStatus.value`), удален устаревший метод `create_anonymous_ticket`.
  - `bots/vk/handlers/admin.py`: парсинг статусов переведен на прямой перебор enum `TicketStatus`.
  - `core/models.py`: поле `FAQNode.depth` аннотировано как `ClassVar[int]`, исключая конфликт с маппингом SQLAlchemy.
- **Интерфейс & Ассеты**:
  - Синхронизированы версии ассетов и бейджи веб-панели до `v0.8.3.5`.

## [0.8.3] — 2026-09-16

### Добавлено
- **Telegram-бот мониторинга и Devops-управления для главного администратора**:
  - Строгий контроль доступа: бот отвечает исключительно пользователю с `TELEGRAM_ADMIN_ID` из `.env`.
  - Мониторинг ресурсов сервера: загрузка CPU, памяти RAM, свободного места на диске и времени аптайма с наглядными шкалами.
  - Состояние Docker-контейнеров: статус, здоровье (healthy/unhealthy), вывод карточки по команде `/status`.
  - Автоматические алерты при сбоях: мгновенное уведомление в Telegram при переходе контейнера в `unhealthy` или неожиданном падении, уведомление при восстановлении сервиса, защита от повторного спама.
  - Интерактивное управление через инлайн-кнопки:
    - Перезапуск отдельных контейнеров или всего стека в один клик (`/restart`).
    - Просмотр последних 35 строк логов любого контейнера (`/logs`).
    - Безопасная перезагрузка физического сервера с подтверждением (`/reboot`).
  - Сервис `tg-monitor` в `docker-compose.yml` с прямым доступом к Docker Engine API через `/var/run/docker.sock`.

## [0.8.1] — 2026-09-15

### Безопасность
- **Startup Guard и Bootstrap Guard**:
  - Автоматическая проверка конфигурации при старте (`core/startup_guard.py`).
  - Блокировка запуска в режиме `production` при обнаружении паролей по умолчанию (`admin123`, `changeme` и т.д.).
- **Харденинг 2FA и защита от перебора**:
  - Лимит попыток ввода OTP-кода (не более 5 ошибок) и повторной отправки (не более 3 раз).
  - Хеширование одноразовых кодов с помощью Argon2id и хранение в Redis с TTL.
  - Возврат корректных HTTP-статусов `401` и `429 Too Many Requests` с заголовком `Retry-After`.

### Оптимизация и надежность
- **Ускорение поиска**: добавлены триграммные GIN-индексы PostgreSQL (`pg_trgm`) для быстрого нечёткого поиска по тикетам и базе знаний.
- **Целостность данных**: настроены внешние ключи с правилами каскадного удаления и обнуления (`ON DELETE CASCADE` / `SET NULL`).
- **Disaster Recovery**: добавлены скрипты резервного копирования и восстановления с проверкой контрольных сумм SHA-256 (`scripts/backup.ps1`, `scripts/restore.ps1`).
- **Мультиязычность (i18n)**: заложена основа локализации интерфейса и сообщений (RU/EN).

## [0.1.0 – 0.6.0] — MVP и базовая функциональность

- Реализация ядра системы на Python 3.11+ и SQLAlchemy 2.0 (asyncpg).
- Гарантированная доставка сообщений студентам через паттерн **Transactional Outbox**.
- VK-бот для приёма обращений студентов по отделам.
- Веб-панель управления на FastAPI и Jinja2 шаблонах.
- Базовые миграции структуры базы данных Alembic.
- Интеграция со скриптами создания администраторов и базовым резервным копированием.

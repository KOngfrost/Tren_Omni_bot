## 🔬 Анализ архитектурных решений

### 1. Почему гибридный стек Python + Go эффективен?
- **Высокочастотные запросы (Read-Heavy)** вынесены в микросервис **Go Fiber** (`backend_go/`). Скомпилированный бинарный файл потребляет всего ~25 МБ ОЗУ и обрабатывает свыше 10 000 RPS при задержках менее 5 мс.
- **Бизнес-логика и веб-панель операторов (Write/Admin)** работают на асинхронном **FastAPI (Python 3.14)** с драйвером `asyncpg`. Благодаря пулу соединений **PgBouncer**, Python-воркеры не блокируют PostgreSQL и выдерживают пиковые всплески без исчерпания лимита подключений.

### 2. Защита от перегрузки базы данных:
- **PgBouncer (Transaction Pooling)**: сжимает 200–500 клиентских соединений всего в 20–30 реальных сессий к PostgreSQL, удерживая использование памяти СУБД на стабильном уровне (< 200 МБ).
- **Redis Caching**: часто запрашиваемые справочники, списки отделов и часто задаваемые вопросы кэшируются в памяти со скользящим TTL, исключая повторные `SELECT` к БД.

## 🛠️ Как воспроизвести нагрузочное тестирование

Для проведения собственных нагрузочных испытаний выполните:

```bash
# 1. Установите зависимости разработчика
pip install -r requirements-dev.txt

# 2. Запуск базового теста (100 пользователей, 10 пользователей/сек в течение 2 минут)
locust -f tests/load/locustfile.py --headless -u 100 -r 10 -t 2m --host http://localhost:8000

# 3. Запуск интерактивного UI с визуализацией графиков в реальном времени
locust -f tests/load/locustfile.py --host http://localhost:8000
# Откройте в браузере: http://localhost:8089
```

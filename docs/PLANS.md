# Планы развития проекта: мобильное рабочее место администратора (Android App) и Telegram Mini App (TMA)

Данный документ описывает стратегию развития платформы, архитектуру и поэтапный план создания мобильного рабочего места для **администраторов отделов** и **суперадминистраторов** в виде нативного приложения для **Android** и **Telegram Mini App (TMA)**.

> **Важный архитектурный фокус:**
> **Основной и целевой пользователь разрабатываемого мобильного приложения (Android) и Telegram Mini App — это администраторы отделов (операторы) и суперадминистраторы платформы.** 
> Обычным студентам в этих приложениях делать нечего: студенты взаимодействуют с сервисом через публичный VK-бот (и в будущем — через чат Telegram-бота). Мобильные клиенты создаются как оперативный служебный пульт управления для дежурных операторов и руководства.

---

## 1. Концепция и ключевые роли

В существующей веб-панели администраторам приходится работать через браузер на ПК внутри Tailscale-сети. Мобильные клиенты (Android App и Telegram Mini App) дают возможность оперативно реагировать на обращения студентов, модерировать систему и проводить аудит безопасности прямо со смартфона.

### Целевые роли:
1. **Администратор отдела (Оператор):**
   - Мгновенные push-уведомления на телефон о новых поступивших обращениях в его отдел.
   - Просмотр очереди заявок своего отдела («Новые», «В обработке», «Передано»).
   - Быстрый ответ студенту из мобильного приложения с шаблонами типовых ответов.
   - Смена статусов заявки («В обработке», «Передано в администрацию», «Передано в локальный Студсовет», «Выполнено»).
   - Управление разделом FAQ и базой знаний своего отдела (добавление, редактирование, удаление).
   - Просмотр списка зарегистрированных участников на мероприятиях отдела.

2. **Суперадминистратор (Главный администратор / Техлид):**
   - **Мобильный журнал аудита (Логи):** просмотр всех действий в системе в реальном времени (попытки входа, смена статусов, действия операторов, IP-адреса) с поиском и фильтрацией.
   - Сквозной просмотр и контроль обращений по всем 4 отделам СУБД (Жилищно-бытовой, Информационный, Корпоративный, Культурно-массовый).
   - Управление учетными записями операторов (создание, смена ролей, привязка VK ID, блокировка).
   - Мониторинг синхронизации времени и здоровья сервиса (/health, дрейф часов, Redis, PostgreSQL, PgBouncer).
   - Просмотр сводной статистики и выгрузка 5-страничных Excel-отчётов.

## 2. Нативное мобильное приложение для Android (Admin Console)

### 2.1. Технологический стек:
- **Платформа:** Android (API 26+ / Android 8.0+).
- **Язык разработки:** Kotlin (Coroutines, StateFlow).
- **Пользовательский интерфейс (UI):** Jetpack Compose, Material Design 3 (тёмная графитовая тема с акцентными цветами статусов).
- **Архитектура:** Clean Architecture (Presentation, Domain, Data) + MVI (Model-View-Intent) с однонаправленным потоком данных.
- **Внедрение зависимостей:** Google Hilt.
- **Сетевое взаимодействие:** Retrofit 2 + OkHttp 4 (интеграция с REST API /api/v1/).
- **Сериализация:** kotlinx.serialization.
- **Локальный кэш (офлайн-режим):** Room DB + DataStore Preferences (кэширование тикетов и логов для быстрого запуска без сети).
- **Push-уведомления:** Firebase Cloud Messaging (FCM) + RuStore Push SDK (оповещение операторов о новых заявках в режиме реального времени).
- **Безопасность:**
  - Вход по логину и паролю администратора с поддержкой 2FA (одноразовый OTP-код в VK).
  - Биометрическая аутентификация (AndroidX BiometricPrompt: отпечаток пальца / Face Unlock) для мгновенного входа без повторного ввода пароля.
  - Хранение токенов в EncryptedSharedPreferences.

### 2.2. Модульная структура Android-приложения:
- :core:network — Retrofit-клиент, перехватчик JWT-токенов, обработка сетевых ошибок.
- :core:database — Room DB, локальные сущности тикетов, логов и отделов.
- :core:designsystem — компоненты Material 3, карточки тикетов, бейджи статусов.
- :feature:auth — экраны входа, ввода 2FA-кода, настройка биометрии.
- :feature:tickets — рабочий стол оператора, фильтры по статусам, детальная карточка обращения, чат ответа студенту, смена статуса.
- :feature:logs — экран системного журнала для суперадминистратора с фильтрацией по действиям и IP.
- :feature:departments — управление структурой отделов и администраторами.
- :feature:faq — управление вопросами и ответами (отдел, вопрос, ответ).
- :feature:monitoring — статус синхронизации времени и здоровья сервисов.

## 3. Telegram Mini App (TMA Admin Workspace)

Telegram Mini App открывается прямо внутри Telegram по кнопке в служебном Telegram-боте операторов и представляет собой адаптивное веб-приложение для дежурных администраторов.

### 3.1. Концепция доступа:
- При запуске Mini App передаются параметры Telegram.WebApp.initData.
- Бэкенд проверяет подпись HMAC-SHA256 токеном служебного бота.
- **Строгая проверка роли:** бэкенд проверяет, привязан ли данный Telegram ID к учётной записи с ролью DEPARTMENT_ADMIN или SUPERADMIN. Если пользователь не является администратором, доступ блокируется с понятным экраном:
  > ⛔ **Доступ ограничен:** данный интерфейс предназначен исключительно для администраторов и суперадминистраторов системы.

### 3.2. Стек технологий TMA:
- **Фронтенд:** React 18, Vite, TypeScript, Tailwind CSS, Telegram UI Kit.
- **Telegram WebApp SDK:**
  - Haptic Feedback (тактильный отклик при смене статусов и отправке ответов).
  - Нативная кнопка MainButton для быстрого сохранения и подтверждения ответов.
  - BackButton для плавной навигации между заявками.
  - Адаптация под тёмную и светлую тему мессенджера.
  - Защита от случайного свайпа вниз при наборе ответа (enableClosingConfirmation).

### 3.3. Возможности TMA:
- Лента заявок своего отдела с цветовой дифференциацией срочности.
- Быстрый набор и отправка ответов студентам.
- Смена статусов и эскалация в администрацию в 2 касания.
- Для суперадмина: компактный экран системных логов и проверка синхронизации времени.

## 4. Служебный Telegram-бот операторов

- **Стек:** Python 3.12+, aiogram 3.x.
- **Назначение:** служебный канал оповещения и быстрых команд для операторов.
- **Функционал:**
  - Приём моментальных уведомлений о новых поступивших обращениях.
  - Кнопка в сообщении «Открыть в Mini App» для перехода к обработке конкретной заявки.
  - Ежедневные сводки и напоминания о «зависших» обращениях.
  - Двухфакторная аутентификация через Telegram (альтернатива или дополнение к VK).

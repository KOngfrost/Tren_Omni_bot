## 1. Доступ к инфраструктуре данных

- **PostgreSQL 16**: слушает внутренний порт `5432` в Docker-сети `oss_bot_net`. Наружу на хост порт не публикуется для исключения несанкционированного доступа.
- **PgBouncer**: легковесный пул соединений, слушает внутренний порт `6432`. Приложение и воркеры подключаются к БД исключительно через PgBouncer.
- **Redis 7**: слушает порт `6379` внутри сети Docker.

### Подключение к PostgreSQL через Docker:
```bash
docker compose exec db psql -U student_user -d student_db
```

## 2. Управление учётными записями через консоль (CLI)

Если веб-панель недоступна или требуется создать первого администратора вручную, используйте встроенные CLI-скрипты:

### 2.1. Создание пользователя веб-панели (`web_users`)
```bash
# Создание постоянного суперадминистратора
docker compose exec bot python scripts/create_web_user.py \
  --username admin \
  --role SUPERADMIN \
  --vk-id 123456789

# Создание оператора отдела (например, Жилищно-бытового)
docker compose exec bot python scripts/create_web_user.py \
  --username operator_zhilbyt \
  --role DEPARTMENT_ADMIN \
  --department "Жилбыт" \
  --vk-id 987654321
```

> [!NOTE]
> Параметр `--vk-id` обязателен при включённой двухфакторной аутентификации (`TWO_FACTOR_ENABLED=true`), так как на этот ID бот отправляет 6-значный OTP-код.

### 2.2. Назначение VK-суперадминистратора (`admins`)
VK-суперадминистраторы получают ежедневные отчёты бота и имеют доступ к управлению прямо в диалоге ВКонтакте:
```bash
docker compose exec bot python scripts/init_superadmin.py \
  --vk-id 123456789 \
  --name "Главный Администратор"
```

## 3. Пул соединений: PgBouncer

В многоворкерном режиме (Uvicorn + фоновые воркеры) прямое подключение к PostgreSQL быстро исчерпывает лимит `max_connections`.

### Особенности конфигурации:
1. **Режим пулинга**: `transaction` (транзакционный). Соединение к Postgres удерживается ровно на время выполнения транзакции и возвращается в пул.
2. **Кэш выражений**: в `core/database.py` отключен кэш подготовленных выражений (`statement_cache_size = 0`) для полной совместимости с транзакционным пулингом asyncpg.
3. **Авторизация**: PgBouncer использует функцию `pgbouncer.get_auth(p_usename)` для прозрачной аутентификации пользователей базы данных.
4. **Миграции**: контейнер `migrate` выполняет DDL-запросы напрямую к PostgreSQL на порт `5432`, минуя PgBouncer.

## 4. Сервис Redis: Сессии, 2FA и блокировки

Redis 7 работает в режиме персистентности AOF (Append-Only File):

### Назначение ключей:
- `session:<id>` — данные сессии авторизованного пользователя (роль, имя, CSRF-токены). Время жизни: 1 час.
- `2fa:<token>` — состояние проверки двухфакторного входа (хеш Argon2id, время жизни 5 минут).
- `cache:*` — кэшированные списки отделов, FAQ и системных настроек.
- `lock:*` — распределённые блокировки фоновых воркеров (Outbox, отчёты).

### Команды диагностики Redis:
```bash
# Проверка доступности
docker compose exec redis redis-cli ping

# Просмотр занятой памяти
docker compose exec redis redis-cli info memory

# Очистка всего кэша
docker compose exec redis redis-cli --scan --pattern "cache:*" | xargs -r docker compose exec -T redis redis-cli del
```

## 5. Миграции базы данных (Alembic)

Любые изменения схемы выполняются строго через миграции Alembic.

```bash
# Применение всех миграций до актуальной версии
docker compose run --rm migrate

# Проверка текущей ревизии
docker compose exec bot python -m alembic current

# Создание новой ревизии миграции (при изменении core/models.py)
docker compose exec bot python -m alembic revision --autogenerate -m "add_new_column"
```

## 6. Резервное копирование и восстановление

### 6.1. Автоматический бэкап
Скрипт `scripts/backup.sh` выполняет:
- `pg_dump` в сжатый архив `.sql.gz`;
- Проверку целостности архива (`gzip -t`);
- Ротацию: сохраняются 7 дневных, 4 еженедельных и 3 ежемесячных копии.

```bash
./scripts/backup.sh
```

### 6.2. Восстановление данных
```bash
# Восстановление из выбранного архива
./scripts/restore.sh /var/backups/oss_bot/oss_bot_2026-09-26.sql.gz

# Перезапуск сервисов после восстановления
docker compose restart bot web-admin
```

## 7. Мониторинг, логи и диагностика

### 7.1. Проверка здоровья сервисов
```bash
# Общий статус контейнеров
docker compose ps

# JSON-ответ healthcheck веб-панели и синхронизации времени
curl -s http://127.0.0.1:8000/health | jq .
```

### 7.2. Чтение логов в реальном времени
```bash
# Ошибки веб-панели
docker compose logs -f --tail=100 web-admin

# Логи фонового цикла бота
docker compose logs -f --tail=100 bot

# Логи сетевого шлюза Caddy и WAF
docker compose logs -f --tail=50 caddy
```

### 7.3. Поиск ошибки по `error_id`
Если оператор прислал код ошибки вида `err_a1b2c3d4`:
```bash
docker compose logs web-admin | grep "err_a1b2c3d4"
```
Команда выведет точный стектрейс и причину исключения.

# Управление базой и администраторами

## Доступ к панели

Панель открывается только внутри tailnet:

`https://имя-вашей-машины.имя-вашей-сети.ts.net`

Войдите учетной записью веб-панели. Если панель недоступна, сначала проверьте Tailscale и контейнеры по инструкции в [DEPLOYMENT.md](DEPLOYMENT.md).

## Роли

| Роль | Возможности |
|---|---|
| Администратор отдела | Просмотр заявок своего отдела, ответы, смена статуса |
| Суперадмин | Все заявки, управление администраторами, назначение отделов, отчеты |

VK-суперадмин определяется записью в таблице `admins` с ролью `SUPERADMIN` и связанным пользователем в таблице `users`. Ежедневные отчеты отправляются всем таким пользователям, у которых есть `vk_id`.

## Добавление администратора

1. Откройте `https://имя-вашей-машины.имя-вашей-сети.ts.net/admin/admins/`.
2. Нажмите «Добавить админа».
3. Укажите VK ID пользователя.
4. При необходимости укажите имя и отдел.
5. Выберите роль `Администратор` или `Суперадмин`.
6. Подтвердите добавление.

Только суперадмин может назначать новые роли и суперадминов. Один VK ID может иметь только одну запись администратора.

Для добавления каждого VK-суперадмина используйте на сервере:

```bash
docker compose exec bot python scripts/init_superadmin.py --vk-id 193626953 --name "Имя Фамилия"
```

## Удаление администратора

Удаление выполняется на странице администраторов кнопкой «Удалить». Операция доступна только суперадмину. Можно удалить обычного администратора или лишнего суперадмина. Удаляется запись из `admins`, пользователь в `users` сохраняется вместе с его заявками и историей.

Нельзя удалить последнюю учетную запись суперадмина или текущую учетную запись. Перед удалением другого суперадмина сначала назначьте замену и проверьте его VK ID.

## Основные таблицы

| Таблица | Назначение |
|---|---|
| `users` | VK-пользователи |
| `admins` | Роль и отдел администратора |
| `departments` | Четыре отдела и их названия |
| `tickets` | Заявки, тема, текст, статус и ответ |
| `ticket_messages` | История сообщений по заявке |
| `web_users` | Учетные записи входа в веб-панель |
| `report_runs` | Защита от повторной ежедневной рассылки |
| `vk_outbox` | Очередь уведомлений пользователям |
| `logs` | Аудит действий |
| `faq_nodes`, `knowledge_base`, `events` | Справка, база знаний и события |

Схема создается и изменяется только миграциями Alembic:

```bash
docker compose exec bot python -m alembic upgrade head
docker compose logs --tail 100 migrate
```

Не редактируйте таблицы вручную в production. Перед изменениями сделайте резервную копию:

```bash
./scripts/backup.sh
```

## Диагностика

Проверка списка администраторов:

```bash
docker compose exec bot python -c "from core.database import async_session_maker; print('DB connection is configured')"
```

Проверка логов панели и бота:

```bash
docker compose logs --tail 200 web-admin bot
```

# Руководство администратора веб-панели (v0.8.2)

OSS Bot предоставляет современную веб-панель управления обращениями студентов, отделами, контентом и правами доступа. Панель защищена и доступна только внутри защищённой сети Tailscale.

---

## 1. Вход и аутентификация

### 1.1. Доступ к панели
Веб-панель доступна по адресу вашей Tailscale-сети:
```
https://oss-web-panel.<tailnet>.ts.net/
```
Для доступа ваше устройство должно быть авторизовано в той же сети Tailscale.

### 1.2. Логин и пароль
1. Перейдите на страницу входа.
2. Введите имя пользователя и пароль.
3. Система защищена от перебора: после 5 неудачных попыток подряд вход с данного IP-адреса временно блокируется на 15 минут (`DBRateLimiter`).

### 1.3. Двухфакторная аутентификация (2FA)
Если в системе включена двухфакторная аутентификация (`TWO_FACTOR_ENABLED=true`) и к вашей учётной записи привязан VK ID:
1. После успешного ввода логина и пароля откроется монолитный экран ввода 6-значного кода подтверждения.
2. Бот мгновенно отправит вам личное сообщение ВКонтакте с одноразовым кодом (например, `481920`).
3. Код действителен в течение 5 минут (`TWO_FACTOR_CODE_TTL=300`). Поле поддерживает как ручной ввод, так и удобную вставку (включая вставку полного сообщения из VK — код извлечется автоматически).
4. При вводе 6 цифр форма отправляется автоматически.
5. Кнопка «Отправить код повторно» снабжена таймером обратного отсчёта (лимит повторных запросов — 3 раза, `WEB_ADMIN_2FA_RESEND_LIMIT`).
6. **Криптографическая защита**: одноразовые коды не хранятся в открытом виде — они хешируются стойким алгоритмом Argon2id и сохраняются в распределённом Redis-хранилище (или memory-хранилище при отсутствии Redis).
7. **Защита от перебора OTP**: допускается не более 5 неверных попыток (`WEB_ADMIN_2FA_MAX_ATTEMPTS`). При исчерпании лимита возвращается HTTP 429 Too Many Requests с заголовком `Retry-After`.
8. При отсутствии привязанного VK ID у администратора суперадмин может привязать его в разделе «Администраторы».

### 1.4. Защита Bootstrap-входа и Startup Guard
- На чистой системе (до создания постоянных пользователей) доступен вход по учётным данным из файла конфигурации `.env` (`WEB_ADMIN_USERNAME` / `WEB_ADMIN_PASSWORD`).
- **Startup Guard (Страж старта)**: при запуске в `APP_ENV=production` система выполняет fail-closed проверку конфигурации (`core/startup_guard.py`). Запуск блокируется, если пароли содержат placeholder-значения (`admin123`, `changeme`, `secret` и т.д.) или пароль короче 12 символов.
- При активной сессии bootstrap вверху экрана отображается **жёлтый предупреждающий баннер** с напоминанием создать постоянного администратора.
- Как только в базе создаётся хотя бы один постоянный суперадминистратор (`SUPERADMIN`), вход по credentials из `.env` **автоматически и безвозвратно блокируется**.

### 1.5. Сессии
- Сессии хранятся в распределённом хранилище Redis (`RedisSessionMiddleware`) и активны в течение 1 часа.
- Благодаря Redis ваша сессия остаётся активной независимо от того, какой рабочий процесс (воркер) сервера обрабатывает запрос.
- Все cookie защищены атрибутами `HttpOnly`, `SameSite=Strict` и `Secure` (при включённом HTTPS).

## 2. Роли и уровни доступа

В системе действуют две роли пользователей веб-панели:

| Возможность | `SUPERADMIN` (Суперадминистратор) | `DEPARTMENT_ADMIN` (Администратор отдела) |
|---|:---:|:---:|
| Просмотр обращений | Все отделы и анонимные | Только своего отдела |
| Ответ на обращения и смена статусов | Да | Только для своего отдела |
| Передача обращения в другой отдел | Да | Нет |
| Управление отделами и ключевыми словами | Да | Только просмотр своего отдела |
| Управление администраторами и web-пользователями | Да | Нет |
| Редактирование FAQ, Базы знаний, Событий | Все отделы | Только своего отдела |
| Просмотр журнала аудита (Логи) | Полный аудит системы | Логи своего отдела |
| Экспорт логов в CSV | Да | Да (своего отдела) |

Изменение роли или деактивация пользователя вступает в силу немедленно: при следующем запросе пользователя права перепроверяются по базе данных.

## 3. Интерфейс и навигация

Веб-панель выполнена в тёмной графитовой гамме с фирменным неоново-розовым акцентом (`#ff4d9d`):
- **Сайдбар и мобильное меню**: удобное переключение между разделами. На мобильных устройствах доступно адаптивное выдвижное меню по кнопке-гамбургеру.
- **Живой поиск**: на всех ключевых страницах (Заявки, Отделы, Админы, FAQ, База знаний, Логи) поле поиска осуществляет мгновенную фильтрацию строк таблицы прямо при вводе текста без перезагрузки страницы.
- **Статусные пилюли-фильтры**: в верхней части списков размещены кнопки быстрой фильтрации по статусам («Все», «Новые», «В обработке», «Выполненные», «Отклонённые») с отображением точного счётчика заявок в каждом статусе.
- **Модальные окна**: просмотр деталей обращений, создание и редактирование записей открываются в модальных окнах, позволяя не терять текущий контекст и позицию прокрутки.

## 4. Работа с обращениями (Заявки)

Раздел `/admin/tickets/` — основной рабочий инструмент операторов:

1. **Список заявок**: отображает номер тикета, тему, имя заявителя (или пометку «Анонимно»), отдел, статус и дату создания.
2. **Фильтрация и поиск**:
   - Поиск по тексту обращения, теме, ID или имени автора.
   - Фильтр по отделам (для суперадмина).
   - Фильтр по статусу кликом на соответствующую пилюлю.
3. **Карточка заявки (Модальное окно)**:
   - Клик по строке заявки открывает карточку с полным текстом обращения и хронологической историей переписки.
   - **Смена статуса**: выбор нового статуса (`В обработке`, `Выполнено`, `Отклонено`) с фиксацией в аудите.
   - **Отправка ответа**: введите ответ в поле ввода. Сообщение сохраняется в истории тикета и ставится в Outbox-очередь гарантированной доставки ВКонтакте.
   - Студент получит сообщение в личные сообщения от имени бота. Если VK временно недоступен, воркер автоматически повторит отправку.
4. **Анонимные обращения**:
   - Если студент выбрал режим «Остаться анонимным», его `vk_id` не сохраняется в базе данных. Такие тикеты доступны для разбора только `SUPERADMIN`, ответ на них носит внутренний характер.
   - Если студент выбрал «Не анонимно», администратор может отправить ему ответ в VK.

## 5. Управление отделами

Раздел `/admin/departments/` позволяет настраивать организационную структуру:
- **Единые карточки отделов**: карточки отделов («Жилбыт», «Культмасс», «Информ», «Корпоративный») оформлены в едином стиле с отображением руководителя, количества заявок и ключевых слов.
- **Маршрутизация по ключевым словам**: для каждого отдела задаётся список ключевых слов. Когда студент создаёт обращение в боте, сервис сопоставляет текст с ключевыми словами отделов (с оптимизацией предзагрузки в память без N+1 запросов) и автоматически маршрутизирует тикет в нужный отдел.
- **Фрейм отдела (`dept_frame`)**: вкладки «Обзор», «Ключевые слова» и «Аналитика» для детального анализа нагрузки.

## 6. Управление администраторами и пользователями

Раздел `/admin/admins/` разделен на две части:
1. **Пользователи веб-панели (`web_users`)**:
   - Список логинов, ролей, отделов и статуса активности.
   - Кнопка **«Добавить пользователя»**: создание нового аккаунта с логином, паролем, ролью (`SUPERADMIN` или `DEPARTMENT_ADMIN`) и привязкой к отделу.
   - Кнопка **«Удалить»**: безопасное удаление аккаунта веб-панели прямо из интерфейса (защита от удаления самого себя).
   - Привязка VK ID: обязательна для пользователей, использующих 2FA.
2. **VK-администраторы (`admins`)**:
   - Назначение администраторов бота, имеющих доступ к админским командам непосредственно внутри переписки с ботом ВКонтакте.

## 7. Управление контентом

- **FAQ (`/faq/`)**: интерактивное дерево вопросов и ответов для автоматического консультирования студентов в боте.
- **База знаний (`/knowledge-base/`)**: статьи и инструкции с привязкой ключевых слов для автоматического ответа на типовые вопросы без участия оператора.
- **События и мероприятия (`/events/`)**:
  - Анонсы мероприятий, дат и объявлений отделов.
  - Поля создания: отдел, название события, дата и время проведения, подробное описание.
  - IDOR-защита: операторы отделов создают и модерируют события строго в рамках своего отдела; суперадминистраторам доступны события всей организации.
  - Учёт регистраций: подсчёт зарегистрированных студентов в реальном времени. При клике на количество регистраций отображается список участников.
  - Прямая интеграция с VK-ботом: события моментально попадают в афишу бота и доступны по кнопке «Мероприятия» и командам «События», «Афиша», «/events».

## 8. Персонализация интерфейса и дизайн-система Glassmorphism

В разделе **«Настройки» (`/settings/`)** администратор может настроить внешний вид панели:
- **Выбор темы оформления**:
  - **Тёмная тема (Dark Graphite)**: глубокий графитовый фон, снижающий нагрузку на глаза в вечернее время, с деликатными розовыми акцентами.
  - **Светлая тема (Rose Peony & Porcelain)**: благородная цветовая гамма белого фарфора (`#fcf9fa`) и мягкого шелковистого градиента пиона (`#e85584` → `#cc3363`), лишённая навязчивого неона и посторонней дымки.
  - **Системная тема**: автоматическая синхронизация с системными настройками операционной системы пользователя.
- **Эффект матового стекла (Frosted Glass)**:
  - Возможность включения/отключения аппаратного размытия подложек (`backdrop-filter: blur(14px)`).
  - При отключении стеклянного эффекта панели переходят в плоский высококонтрастный режим для экономии ресурсов видеокарты.
- **Строгий деловой стиль**:
  - Служебный интерфейс панели свободен от неформальных эмодзи. Вся навигация выполнена на векторных SVG-иконках.
  - Информативная карточка профиля оператора в сайдбаре отображает аватар-сквиркл, имя пользователя и бейдж роли (`Суперадмин` / `Админ отдела`).

## 9. Журнал действий (Логи)

Раздел `/admin/logs/` обеспечивает полный аудит безопасности системы:
- **Ограничение доступа**: вкладка «Журнал» и выгрузка логов доступны **исключительно суперадминистраторам** (`SUPERADMIN`). Для администраторов отделов данный раздел скрыт в интерфейсе и защищён проверкой прав на бэкенде.
- Фиксация каждого значимого события: успешные и неуспешные входы (с фиксацией IP), отправка ответов на тикеты, смена статусов, создание/редактирование пользователей.
- Запись содержит дату/время, имя администратора, тип действия, IP-адрес и подробности.
- Кнопка **«Экспорт в CSV»** позволяет выгрузить журнал (до 10 000 записей) в защищённый CSV-файл с кодировкой UTF-8 BOM и экранированием полей.

## 10. REST API v1

Для внешних интеграций доступен REST API с документацией:
- **Swagger UI**: `https://oss-web-panel.<tailnet>.ts.net/docs`
- **ReDoc**: `https://oss-web-panel.<tailnet>.ts.net/redoc`
- **Эндпоинты v1**:
  - `GET /api/v1/departments/` — список отделов
  - `POST /api/v1/departments/` — создание отдела (требует прав суперадмина)
  - `GET /api/v1/departments/{id}` — получение информации об отделе
  - `PUT /api/v1/departments/{id}` — обновление отдела
  - `DELETE /api/v1/departments/{id}` — удаление отдела
  - `GET /api/v1/stats` — сводная статистика обращений по статусам и отделам
  - `GET /metrics` — сбор метрик Prometheus

Все входящие и исходящие данные валидируются строгими схемами Pydantic v2.

## 11. Что делать при возникновении ошибки

Система спроектирована так, чтобы в случае непредвиденных сбоев пользователи и операторы не оставались в неведении:

1. **Сообщение на экране**:
   > **Произошла ошибка. Пожалуйста, сфотографируйте экран и отправьте техническому администратору.**
2. **Код ошибки (`error_id`)**:
   - На странице ошибки отображается уникальный идентификатор, например: `err_a1b2c3d4e5f6`.
   - В логах сервера и системе мониторинга Sentry ошибка регистрируется под этим же `error_id`.
3. **Действия оператора**:
   - Сделайте скриншот или фото экрана с кодом ошибки.
   - Отправьте снимок техническому администратору.
   - По указанному коду технический специалист за считанные секунды найдет точное место в коде, стек вызовов и причину сбоя.
